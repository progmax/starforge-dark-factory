# Independent acceptance design and interpretation limits

The only domain input is the supplied complete Stage1 specification. This audit is frozen before implementation and organizer example-test reads. It does not prescribe language, framework, database, locking algorithm, ID format, export layout, token encoding or hash encoding. No service/browser/Docker was executed by the auditor.

`acceptance.py` uses Python standard library HTTP requests and unittest. It only contacts HTTP when explicitly given `--run` and two distinct origins. Every business scenario resets a synthetic six-user fixture. The HTTP adapter validates response JSON/UTF-8, universal error envelope, no5xx,204 emptiness and measured request budget. Per-record assertions check exact specified values, receipt IDs/timestamps/linkage and default fields while allowing additional response fields unless replay JSON equality requires the whole original body. Unknown request fields remain part of parsed-body idempotency identity while ignored for endpoint semantics.

The ledger maps each normative clause to named test methods or mandatory inspection IDs. Test methods contain bounded data matrices and controlled scenarios, not implementation mirrors. No test imports product code. Pure author checks collect tests, validate ledger links and independent rounding/timestamp oracles, with zero HTTP activity. No installation is necessary for the independent suite.

Concurrency uses a worker barrier and up to50 concurrent calls, with a fresh key or controlled same-key group. Identical groups have exactly one201 and49 identical200 responses; conflicting parsed bodies have one winning first-use and conflicts for the other group. Distinct-key spends cannot exceed starting funds. Terminal request races allow any permitted winner but at most one payment. Net settlement cycles with all zero balances must succeed; sequential-transfer affordability is not a valid oracle. Export snapshots taken during transfers are imported into the independent peer and checked by HTTP rather than parsing state.

The source and destination must be independently instantiated from the exact same image, with separate stores/ports and no shared files. Export/import preservation compares all saved records, tokens, original receipts and body replays. Destination-only credentials are removed. Repeat imports restore original state after new writes; failed keys remain reusable. Source removal and invalid implementation-specific state validation need Verifier setup/source awareness and are explicit I-10/I-11 duties.

Finite tests cannot prove never-negative transient internals, forever-valid tokens, real password hashing, absence of outbound dependencies or all resource/delivery facts. Required inspection evidence is a separate acceptance gate. Sequential reads of different wallets are not treated as an atomic snapshot; balance conservation under active writes uses exports imported into the peer. Wallet sums are checked only after writers complete or inside a restored snapshot.

Interpretations justified by the text, with no undocumented rejection codes or encodings:

- §10 explicitly exempts export/import from auth despite §6's earlier exception list. §10 explicitly gives all test control calls10s; that controls the timeout adapter, including export/import.
-204 has no body. JSON media type/charset is required for responses carrying JSON; no test demands a JSON body on204.
- Numeric JSON1 and1.0 are the same number; bool is a different JSON type even where Python equality would call True==1. Amount outputs may use any integral numeric JSON encoding, never strings/bools. Notes are compared as UTF-8 content after JSON parsing; JSON wire escape spelling is not constrained by the verbatim-content clause.
- Idempotency identity includes user/method/path/key and complete parsed object, including ignored fields; array order matters. Unknown fields are ignored by endpoint processing, not deleted before key equality. A successful key must resolve before current field/resource validation after auth and object parse. Nonobject/unparseable bodies have no guaranteed replay.
- `POST /requests` optional note defaults empty by the shared ordinary note usage and request example; §8 gives its length rule. Request visibility is not a field and must not control resulting payment; a payer chooses visibility only on pay. Unknown note/amount fields in pay bodies must be ignored.
- Split caller omission means only listed participants share the stated total; do not silently append caller. Zero shares explicitly create requests and must be payable for zero without triggering ordinary user-input amount>=1 validation. There is no proof of a prior payment required before a split.
- Settlement malformed outer batch shape/count/nonobject members422 takes precedence over generic type rule; wrong typed ordinary entry handle fields use generic400, while amount/note/visibility use422. Within one entry simultaneous error ordering is unspecified; only distinct entry input ordering before funds is asserted.
- User handle pattern/uniqueness is normative; additional recipient-handle format error ordering versus404 is not forced by frozen tests. Email form local@domain has no stricter standards/domain-dot/casefolding rule; only unambiguous valid/invalid forms used. Empty/missing local/domain are invalid; no undocumented maximum length enforced.
- Balances cannot exceed2^53 per-wallet or become negative. Overflow rejection status/code is unspecified; tests require a4xx atomic refusal without asserting its exact code. The seed total can exceed2^53 across multiple wallets. Internal arithmetic must still be exact.
- Export state is opaque. The suite rejects envelope/state-type errors and verifies unchanged portability. It does not assume empty `{}` or a renamed internal key is invalid; source-aware invalid-state checks remain mandatory.
- IDs opaque<=64; no prefix/UUID/count/gaplessness assertions. Seeded timestamp generation is not prescribed, but returned timestamps must be valid and preserved in import. Existing records need not be replayed against net balances.
- Activity same-second order unspecified and concurrent-write stable pagination explicitly unnecessary. Tests assert descending timestamps, page sizes/has_more/membership, and use separated timestamps for a deterministic newest item. No ID tiebreaker is imposed. Request tied timestamps likewise receive no invented ordering.
- Authentication vs other independently invalid fields, duplicate header/query keys, empty decline/cancel bodies, unknown routes/methods, unsupported currency fixtures and duplicate/otherwise inconsistent seed fixtures have no additional frozen precedence oracle. Use unambiguous inputs; source inspection must still rule out5xx and invariant violations.
- Export/import can change the currently seeded population/total by replacement; conserved total is the seed total of that restored snapshot. This resolves §1's wording in conjunction with §10's mandatory portability and replacement.

Residual ambiguity is reported, never silently weakened into acceptance. The audit is a complete clause mapping plus executable observable checks and mandatory inspections, not a claim of exhaustive mathematical state-space execution.
